# M3: users, login and the `CurrentUser` extractor

Goal: real user accounts, password login with cookie sessions, a `create-admin` command-line
subcommand, and an extractor that makes any handler require login.

Crate versions checked in a scratch project on 2026-10-10. They all work with axum 0.8.9:

- **argon2 0.6** hashes and verifies a password; its errors work with `?` directly.
- **rand 0.10** generates a secure random session token.
- **axum-extra 0.12** sets a cookie with `HttpOnly`, `SameSite=Lax` and `Path=/`.
- **A custom extractor** compiles as a plain `async fn` in the trait, with no extra macro.

---

## The topics, and the Rust tools for each

### 1. Password hashing: `argon2`, and keeping CPU-heavy work off the async threads

- The whole API is two calls:
  - `Argon2::default().hash_password(pw.as_bytes())?.to_string()` produces a self-describing
    string like `$argon2id$v=19$m=19456,t=2,p=1$<salt>$<hash>`, which you store in `password_hash`.
  - `verify_password(pw, &PasswordHash::new(&stored)?)` checks a password against it.
  - In version 0.6 the salt is generated for you.
- **This is the `spawn_blocking` case.** One hash takes about 25 ms on the desktop in release
  mode, and noticeably longer on the Pi. In a **debug** build it took about 400 ms, because
  dependencies aren't optimized there. So in `Cargo.toml`, have dev builds optimize this crate:
  ```toml
  [profile.dev.package.argon2]
  opt-level = 3
  ```
- **What you'll learn from `spawn_blocking`.** The closure runs on another thread, possibly after
  your function has returned. So it must **own** everything it uses: a `move` closure, `String`
  rather than `&str`, and a `'static` requirement. Expect your first real ownership errors here.

### 2. Sessions: a database table plus a cookie

- **The flow:** on login, generate a random token, store it in an `auth_sessions` table, and set
  it as a cookie. On every request, look up the cookie value in that table to find the user.
- **The token:** `let bytes: [u8; 32] = rand::random();`, then turn it into hex text:
  `bytes.iter().map(|b| format!("{b:02x}")).collect::<String>()`. `collect` builds a `String`
  from an iterator of strings, like `"".join(...)` in Python.
- **Cookies:** `axum_extra::extract::cookie::CookieJar` is an extractor for reading cookies, and
  also something you can *return* to set or remove them. Returning `(jar, Redirect::to("/"))`
  works because tuples of `IntoResponse` types are themselves `IntoResponse`.
- **Cookie attributes:**
  - `HttpOnly`: JavaScript can't read the cookie.
  - `SameSite=Lax`: another site can't make the browser send it in a POST, which is the main
    protection against forged form submissions.
  - **Not `Secure`.** The app is served over plain HTTP inside the VPN, and a `Secure` cookie is
    never sent over HTTP. That would look like "login always fails".
- **Expiry, without a date library yet.** Store `expires_at` in the same text format as
  `created_at`, computed in SQL: `strftime('%Y-%m-%dT%H:%M:%SZ', 'now', '+30 days')`. Text in
  this format compares correctly with `>`, so `WHERE expires_at > <now>` works. `chrono` can
  wait until M6.

### 3. Forms: `Form<T>` and `serde::Deserialize`

- `#[derive(Deserialize)] struct LoginForm { username: String, password: String }`, with a
  handler that takes `Form(form): Form<LoginForm>`. Roughly a pydantic model for form data.
- **Axum rule:** an extractor that reads the request **body** (`Form`, `Json`) must be the
  **last** argument. It's a different trait (`FromRequest`), and the body can only be read once.
  Breaking the rule produces the `Handler` trait error from M1; `#[debug_handler]` explains it.
- **Don't reveal which part was wrong.** Show the same "invalid username or password" whether the
  user doesn't exist or the password is wrong.

### 4. The `CurrentUser` extractor: implementing an axum trait yourself

```rust
impl FromRequestParts<Arc<AppState>> for CurrentUser {
    type Rejection = AppError;          // what is returned if extraction fails
    async fn from_request_parts(parts: &mut Parts, state: &Arc<AppState>)
        -> Result<Self, Self::Rejection> { … }
}
```

- **New concept: associated types** (`type Rejection`). The trait leaves a type slot that each
  implementation fills in.
- Once implemented, **any handler that takes `user: CurrentUser` as an argument requires login.**
  It's like a FastAPI dependency, but the protection follows from the handler's signature.
- **Rejection:** add an `AppError::Unauthorized` variant whose `IntoResponse` redirects to
  `/login`.
- Inside the extractor you can call other extractors:
  `CookieJar::from_request_parts(parts, state).await`.
- **Module privacy:** the extractor lives in `src/auth/`, but `AppState` is defined in `main.rs`.
  A child module can use its parent's private items through `crate::AppState`. Privacy in Rust
  hides things from *outside*, not from code inside.
- **Old tutorials won't match.** They show `#[async_trait]` on this impl; in axum 0.8 it's a plain
  `async fn` in the trait. Using `Option<CurrentUser>` as an argument (a page that works whether
  or not you're logged in) needs a second trait, `OptionalFromRequestParts`. Add it only if needed.

### 5. A command-line subcommand: `clap`

Usage: `ttrpg-scheduling create-admin marek` creates the first account. With no subcommand, the
binary starts the server as usual.

```rust
#[derive(clap::Parser)]
struct Cli { #[command(subcommand)] command: Option<Command> }

#[derive(clap::Subcommand)]
enum Command { CreateAdmin { username: String, display_name: String } }
```

Each subcommand is an **enum variant with fields**, so `main` turns into a `match` over the
parsed command. clap is an attribute-driven derive, like thiserror, and generates `--help` for
you. Reading the password from stdin with `std::io::stdin().read_line(...)` is fine; the text
will be visible as you type it.

### 6. New module layout: a directory module

```
src/auth/mod.rs        # declares: pub mod password; pub mod session; …
src/auth/password.rs   # hash(), verify()
src/auth/session.rs    # create/delete/lookup in auth_sessions
src/auth/extractor.rs  # CurrentUser
```

`mod auth;` in `main.rs` loads `src/auth/mod.rs`, which plays the same role as a Python
package's `__init__.py`.

## Step 1: your task

1. Add the dependencies and the profile setting.
2. Run `sqlx migrate add create_auth_sessions` and write the table yourself.
   - Should `expires_at` have a `DEFAULT`, or should the `INSERT` set it every time? Think about
     who decides how long a session lasts.
   - SQLite only enforces `ON DELETE CASCADE` when foreign keys are on. sqlx turns them on by
     default (verified in M2), so deleting a user will delete their sessions.
3. Run `sqlx migrate run` and check the result with
   `sqlite3 data/dev.db '.schema auth_sessions'`.
